Изменения безопасности от 17 октября: пустой allowlist закрывает доступ; открытый бот требует `TELEGRAM_ALLOW_ANY_USER=1`. По умолчанию поддерживаются только личные чаты. Для удалённого backend требуется HTTPS. Подробности и лимиты: [security fixes](../docs/reviews/security-fixes-2026-10-17.md).

# Hromi Telegram bot

Отдельный dependency-free процесс Telegram-бота. Он принимает фотографию,
вызывает защищённый внешний API Hromi backend, следит за очередью и возвращает
готовое изображение в Telegram.

## Сценарий

1. Пользователь отправляет фото; `/start` и `/model` показывают список моделей.
2. Бот получает актуальные разрешённые workflow из `GET /api/v1/models`.
3. Для каждого workflow создаёт отдельное задание с одной и той же фотографией.
   Задания отправляются последовательно, поэтому достаточно квоты на одну активную job.
4. Бот показывает название модели, номер запуска и состояние очереди.
5. Каждый успешный результат возвращает отдельным изображением с названием модели
   и workflow. Если один workflow завершился ошибкой, остальные продолжают работу.

JPEG, PNG и WebP до 8 МБ поддерживаются как фото или image-документы.
Обычно каждый запуск занимает 5–10 минут; полное сравнение занимает больше времени.
В серию входят все workflow, которые возвращает API, включая проверочный passthrough.

Каждый пользователь может отправить только одно фото на сравнение одновременно.
Следующее принимается после завершения всей серии.

GPU VM вручную запускать не нужно: backend worker сам поднимает её перед
обработкой и применяет общий idle timeout после опустошения очереди.

## Настройка

Создайте бота через `@BotFather` и скопируйте конфигурацию:

```bash
cd telegram-bot
cp .env.example .env
```

В `telegram-bot/.env` задайте:

```env
TELEGRAM_BOT_TOKEN=<token от BotFather>
HROMI_BASE_URL=http://127.0.0.1:8091
HROMI_PUBLIC_API_KEY=<тот же ключ, что в backend/.env>
```

В `backend/.env` должен быть тот же ключ длиной не менее 32 символов:

```env
HROMI_PUBLIC_API_KEY=<случайный секрет минимум 32 символа>
```

После изменения `backend/.env` перезапустите backend. Не коммитьте оба `.env`.
Для закрытого тестового бота задайте `TELEGRAM_ALLOWED_USER_IDS=123,456`.

## Запуск

```bash
make run
```

или из корня репозитория:

```bash
make telegram-bot
```

Long polling и webhook нельзя использовать одновременно. Если раньше был
настроен webhook, удалите его через Bot API перед запуском этого процесса.

## Надёжность

- Связи Telegram update ↔ Hromi job хранятся в
  `telegram-bot/data/telegram-bot.sqlite3`.
- `Idempotency-Key` включает Telegram `update_id` и идентификатор модели, поэтому
  повтор отправки одной модели не создаёт вторую генерацию.
- Список моделей, исходное фото, текущая job и позиция серии сохраняются в SQLite.
  После перезапуска серия продолжается; после завершения фото удаляется из записи серии.
- Незавершённые job восстанавливаются после перезапуска процесса.
- Для каждого пользователя backend проверяет ownership и собственную квоту.
- Бот никогда не обращается к ComfyUI или управляющим `/vm/*` endpoints напрямую.
- Base64 фотографий, токены и API key не записываются в журнал.

## Команды

- `/start` и `/help` — инструкция и список моделей;
- `/model` — показать модели для сравнения;
- фотография или image-документ — запустить сравнение всех моделей.

## Проверка

```bash
make test
```

Реальный запуск требует доступ к `api.telegram.org`, запущенный backend и два
секрета. Unit-тесты используют только локальные заглушки и сеть не вызывают.


Состояние каждого этапа серии, progress message ID и подтверждённая доставка
сохраняются в `comparison_steps`. Временные ошибки Telegram повторяются без
перезапуска. Постоянные ошибки завершают этап или серию и освобождают пользователя.
Если процесс прервался после сохранения доставки, эта картинка повторно не отправляется.
Сбой между фактической отправкой Telegram и записью подтверждения в SQLite всё
ещё может привести к повторной доставке: общей транзакции между ними нет.

Бот исключает модели с `availability=missing`. Если VM выключена и проверок ещё
не было, модели со статусом `unknown` остаются в списке для автоматического старта.
